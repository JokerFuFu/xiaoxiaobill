## 1. 问题

项目已定名「小小账单」并完成项目层自有化,但**产品本体仍浑身「小遥」**:浏览器标签、侧栏、登录页、AI 人格自称、年度报告水印、导出文件名共 15+ 处旧品牌串;logo/favicon 是上游视觉;「关于作者」页整页是原作者个人推广(头像/微信/交流群二维码)。同时设计语言半新半旧——首页已是 AI 原生风格、token 体系已建立,但其余 20 个页面存在硬编码样式与不一致刻度。痛的人是:① 每天使用的用户本人与家人(品牌割裂、"用别人的东西"感);② 未来看到仓库的访客(无法作为独立作品呈现,且原作者个人联系方式出现在产品内对双方都不合适)。

## 2. 假设

为「让小小账单成为可署名、可分享的自有作品」做「全触点品牌统一 + 关于页致谢改造 + 设计语言按既有基准收口」,使用者对产品的信任与归属感因「界面/文档/仓库呈现一致的单一品牌身份,且开源血统在关于页与 README 中清晰可查」而建立——品牌的一致性传递"这是被认真维护的作品",完整的致谢链传递"这是合规、体面的二次创作"。

## 3. 范围

**IN**:
- 前端 UI 全部旧品牌串替换(15+ 处,见 eval BR 组)
- AboutAuthor.vue → About.vue「关于小小账单」(项目介绍 + 完整致谢链 + MIT 双版权说明),移除原作者个人推广物料
- 新 logo/favicon(AI 生成草案 → 用户挑选定稿)
- localStorage `xiaoyao_*` → `xiaoxiao_*` 带迁移函数(不丢用户偏好)
- 设计语言收口:全 21 页视觉审计 → P0 项按既有 token 基准修复
- docs 顶层 10 个 md 品牌替换;上游运营物料归档至 `docs/archive/`
- docker-compose 品牌化 + NAS 生产实例迁移;GitHub/gitea 仓库改名 + 链接收口

**OUT(本期不做)**:

- 与上游 dtsola 仓库的代码同步
- i18n 多语言
- 对外推广物料创作(公开决策未定,见迭代路线图 B 类)

**刻意 CUT(记录取舍)**:

## 4. 用户体验

- **基准**(已存在,可点开):本地 `npm run dev` → `http://localhost:3000` 的首页 AI hero(commit `547dbfc`)即目标风格锚点
- **品牌预览页**(plan Task 6 产出,拍板用):单文件 HTML,内含 logo 草案×3、色板(沿用 #007AFF 体系)、侧栏/登录页/AI 欢迎屏三个 mockup 对照;用户从中挑选 logo 后进入替换
- **终态体验**:用户打开 `192.168.10.3:8888` → 标签页「小小账单」+ 新 favicon → 登录页新 logo +「小小账单」→ 侧栏新品牌 → AI 页「你好，我是小小」→ 导出文件名「小小对话-*.png」→ 关于页讲述项目故事并致谢两位上游作者——全程无一处旧品牌,且旧用户的导航折叠/筛选偏好原样保留

## 5. 验收标准

**执行层全量判据在 eval 文件**(`docs/superpowers/evals/2026-07-13-品牌化-eval.md`,BR/VI/LS/DC/DP/E2E 六组 23 条,铁律:只增不删,agent 只翻 passes)。此处记意图:

- **零残留**(BR-08、E2E-01):以「全仓 grep + 构建产物 grep」双层收口,白名单显式枚举(致谢语境/关于页/归档区),防止批量替换误伤上游专名——上游项目名是致谢的一部分,必须保留
- **零偏好丢失**(LS 组):迁移函数有单测 + 端到端验证,旧用户无感升级
- **零功能回归**(E2E-03):品牌化是纯呈现层改动,前后端测试与 lint 必须保持全绿
- **生产落地**(DP-02):以 NAS 实例(真实用户环境)验收,不以本地为准
- **人工兜底**(E2E-02):9 屏走查表,机器 grep 不能发现的视觉级露出(图片内文字、favicon)靠这条

本项目非 AI 行为变更(人格名只是文案),**不需要 Evals(AI 行为合约)段**。
