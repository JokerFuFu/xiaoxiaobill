## 1. 背景与现状

小遥账单助手是一个**隐私优先**的个人账单分析工具（Flask + Pandas 后端，Vue 3 + Vite 前端）。经全面探索确认，项目**功能已相当完备且工程底子扎实**：

- 后端 21K+ 行，四层清晰（`api/` 13 蓝图 / `services/` 21 模块 / `parsers/` 5 解析器 / `utils/`）
- 前端 19 个页面、6 个 Pinia store
- 四大新功能（多用户、AI 问答、邮箱 IMAP 自动导入、加密 PDF/ZIP 解密）链路全通
- 架构亮点：按文件签名（mtime+size）自动失效的 DataFrame 缓存、`RLock` + 原子写（`.tmp`→`replace`）、目录级多用户隔离、werkzeug 密码哈希、敏感文件 `0600`

**但存在明确的工程与体验短板，正是本轮要处理的：**

1. **几乎零测试、无 CI**：后端测试仅覆盖邮箱功能（8 个 `test_mailbox_*.py`），核心的账单解析（`parsers/`）与数据分析（`services/analysis.py` 964 行 / 25 函数）**毫无测试**；前端**完全零测试**、无 ESLint/Prettier；**无 `.github/workflows`**。在"AI 代写代码"的协作模式下，缺自动化测试意味着导演（用户）失去了"改坏了没"的唯一兜底。
2. **一批已知小问题**：前端 401 处理走 `window.location.href` 而非 router、2 处裸 `except`、113 处遗留 `console.log`、`.superpowers/sdd/` 遗留 3 条 fast-follow、设计文档滞后于代码。
3. **可维护性债**：3 个超长文件（`Insights.vue` 2610 行、`Settings.vue` 1793 行、`api/analysis.py` 1571 行）、表格/ECharts 逻辑 10+ 处重复。
4. **体验待打磨**：左侧导航项过多、折叠逻辑不顺；首页布局未突出 AI 助手；整体视觉/交互一致性可提升。

### 1.1 威胁模型说明（决定"不做什么"）

项目**暂不公开**、当前为本人/小范围使用。因此**运行时隐私加固（B 类：AI 上传脱敏、邮箱授权码/AI Key 落盘加密）在此阶段属过早优化（YAGNI），本轮不做**，仅作为"发布前待办"记录在案（见 §9）。本轮聚焦工程地基、已知问题、可维护性与体验。

## 2. 目标

**总目标**：在不破坏现有功能的前提下，为项目补上"AI 可安全代改"的工程地基，逐项清掉已知问题，优化可维护性与使用体验，并稳步补齐用户价值——使项目进入"可持续、可放心迭代"的状态。

**三条线目标：**

| 线 | 目标 |
|---|---|
| **① 修问题** | 建立"测试 + CI"安全网；关闭已知缺陷；回填滞后文档 |
| **② 优化现有功能** | 拆分超长文件、抽通用组件、统一 API/错误反馈；整理左侧导航、重构首页布局、打磨整体视觉与交互一致性 |
| **③ 开发新功能** | (a) 报表/账单导出（分析报告 → PDF/Excel）；(b) 更多银行/来源解析器 |

---

## 3. 成功标准（可验证）

1. `parsers/` 全部 5 个解析器与 `services/analysis.py` 核心函数具备 pytest 回归覆盖；前端 api/store 具备 Vitest 骨架。
2. GitHub Actions（或等价 CI）在每次改动自动运行 pytest + vitest + lint，红/绿可见。
3. §5 Track ① 的已知问题清单逐项关闭并有记录。
4. 3 个超长文件均拆分至单文件 < 500 行（项目规范线）。
5. 左侧导航项精简、折叠逻辑正确；首页 AI 助手为主视觉置顶放大、其余内容下移；整体视觉与交互一致性经人工验收通过。
6. 两个新功能上线可用，且各自带测试。
7. 全程无功能回归：既有 API 保持向后兼容，既有页面功能不丢失。

## 6. 分期编排（Plan 将写在同一文件、内部分 Phase）

> 排序原则：**地基先行**（测试/CI 是后续一切改动的安全网）→ 修问题 → 在测试保护下重构 → 拆完再做体验打磨 → 新功能。

| Phase | 内容 | 依赖 | 完成定义（DoD） |
|---|---|---|---|
| **P0 · 地基** 🔴 | 后端 pytest（`parsers/` + `analysis.py` 核心）；前端 Vitest 骨架 + ESLint/Prettier；GitHub Actions CI | 无 | CI 绿；核心解析/分析有回归覆盖 |
| **P1 · 修问题** 🟠 | 401 走 router、裸 except 收窄、console 规范化、SDD 三条 fast-follow、文档回填、Monthly TODO | P0 | 问题逐项关闭；测试保持绿 |
| **P2 · 结构优化** 🟠 | 拆 `api/analysis.py`→子蓝图、拆 `Insights.vue`/`Settings.vue`、抽通用表格 + ECharts 封装、统一 API 响应 | P0 测试护航 | 超长文件 < 500 行；功能零回归 |
| **P3 · UX/视觉打磨** 🟠 | `design-taste-frontend` audit → 精修设计系统与交互一致性、左侧导航 IA + 折叠、首页 AI 置顶放大 | P2（拆分后打磨更干净） | 视觉/交互一致；导航精简；首页新布局；截图人工验收 |
| **P4 · 新功能** 🟢 | 报表/账单导出（PDF/Excel）、更多银行/来源解析器 | P0 测试框架 | 功能可用；各带测试 |

## 7. 测试与验收策略（横切所有 Phase）

- **每个 Phase 收尾 CI 必须绿**，红则不进下一 Phase。
- **重构类改动（P2）**：改动前后各跑一遍 P0 建立的全套测试作回归对比，确保行为不变。
- **新解析器（P4）**：每个来源配 fixture 测试；**fixture 必须使用脱敏/构造样本，严禁提交真实账单文件入库**（同时满足仓库卫生/代码脱敏 A 类要求）。
- **前端视觉/布局（P3）**：自动化无法评判美观与手感，采用**本地预览 + 截图人工验收**；Vitest 仅保证组件不报错、交互逻辑不回归。
- 每个 Phase 在 Plan 中都提供**任务拆解 + DoD + 可运行的验证命令**，供 Claude Code 执行、用户逐 Phase 验收。

---

## 8. 关键约束与原则

1. **API 向后兼容**：既有 API 契约不破坏（拆 `api/analysis.py` 为子蓝图时保持原路由路径不变）。
2. **功能零回归**：既有页面功能与 `keep-alive` 保活行为不丢失。
3. **测试数据零真实隐私**：所有测试 fixture 为构造/脱敏数据。
4. **视觉打磨而非重设计**：保留现有 Apple 风设计语言，只提升协调性与交互一致性。
5. **单一事实源**：Spec/Plan 用中文书写、标识符保留英文；不维护中英双份以防漂移。
6. **小步可验收**：每个 Phase 独立可交付、可回滚、可验收。

## 9. 发布前待办（本轮不做，公开前另开 Spec）

以下为"若将来决定公开/多用户对外"时需处理的运行时隐私与安全项，此处仅登记，不排进本轮 Phase：

- AI 问答上传前对交易 DataFrame 脱敏（对方名/姓名/卡号 → 序号）+ 设置页知情同意提示；或提供本地 LLM 选项。
- 邮箱授权码、AI API Key 落盘**加密存储**（现为 `0600` 明文）。
- README "数据完全本地处理、不上传任何服务器" 宣传口径与 AI 上云现实对齐。
- 密码强度下限从 4 位提升至 8+；生产强制 `SESSION_COOKIE_SECURE=True` + HSTS。
- AI 异常日志不再打印 `r.text[:400]`（可能含用户数据）。
- ZIP 解压对 `namelist()` 逐项校验 `..`/绝对路径。
