## 3. 设计语言优化

**现状**：Phase3 已补齐设计 token（commit 976c511）、首页已重做为 AI 原生风格 hero（commit 547dbfc）、EChart/DataTable 已封装为通用组件（b924bff）。即：设计语言升级**已有方向和地基**，缺的是全站统一铺开。

**建议路径**：
1. **视觉审计**（半天）：截取全部 21 个页面现状，对照首页新风格列出不一致项（配色、圆角、间距、卡片、表格、空态、加载态）
2. **品牌视觉定义**：新 logo + 主色板 + 字体规格，沉淀进设计 token（CSS 变量），替换 `assets/styles/main.css` 中的旧值
3. **逐页铺开**：按「高频页优先」顺序（首页✅ → 分析页 → AI 页 → 设置/管理页），复用已封装组件收敛样式
4. 每一步产出可点开的预览（Product Spec 第 4 段的「用户体验 URL」直接用本地 dev server + 截图归档）

## 5. 建议节奏（spec → plan → eval → 执行）

1. **决策会**：敲定 D1–D6（一条消息回复即可）
2. **三件套**：产出 `spec`（品牌化+设计语言的建什么/不建什么）、`plan`（下方 PR 划分细化）、`eval.md`（逐触点 checklist：id + 断言 + 验证命令 + passes，判据只增不删；至少 1 条端到端判据，如「全仓 grep 小遥/xiaoyao 仅致谢白名单命中 + 构建通过 + 登录→上传→分析→AI 对话全流程无旧品牌露出」）
3. **执行 PR 划分**（每个独立可验收）：
   - PR1 文案与人格：2.1 全部触点 + D1/D3
   - PR2 视觉资产：logo/favicon/token 主色（依赖 D2/D6）
   - PR3 localStorage 迁移（D4）
   - PR4 docs 批量 + 运营物料归档
   - PR5 部署与仓库迁移：docker-compose 改名 + NAS 重部署 + repo 改名（D5，放最后、单独窗口执行）
4. **收尾**：重截产品截图 → 更新 README 功能预览 → 群晖重新部署验证

## 6. 风险清单
